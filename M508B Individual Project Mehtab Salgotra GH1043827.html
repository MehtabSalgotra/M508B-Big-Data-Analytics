1. Introduction & Business Problem¶

Business Context: For this project, I acted as a data scientist tasked with automating our company's customer support routing. Currently, our support team manually reviews thousands of incoming emails to decide if they belong to "Tech Support," "Sales," or "Policy." This process is slow and expensive.

Project Objective: My goal was to build a Natural Language Processing (NLP) pipeline that automatically classifies these uncleaned raw text messages into topics. I aimed to compare a simple statistical approach (TF-IDF) against more complex deep learning methods (LSTM) to see which one offered the best balance of accuracy and efficiency for our specific data.

Data Strategy: I selected the 20 Newsgroups dataset (uncleaned version) to simulate real-world noise. I focused on four distinct categories: sci.space, rec.autos, comp.graphics, and talk.politics.mideast.

Data Access Method:

  • Scikit-Learn Library: We accessed the data using the sklearn.datasets.fetch_20newsgroups loader.
  • Documentation Link: https://scikit-learn.org/stable/modules/generated/sklearn.datasets.fetch_20newsgroups.html

2. High-Level System Design¶

The overall NLP pipeline implemented in this project follows a modular, end-to-end design. Each component plays a specific role in transforming raw textual data into meaningful predictions.

System Components

Data Ingestion Raw, uncleaned text data is loaded directly from the scikit-learn fetch_20newsgroups dataset. This simulates real-world scenarios where textual data contains noise such as headers, footers, and irrelevant metadata.

Preprocessing Layer The preprocessing stage standardizes text by:

Lowercasing

Removing non-alphanumeric characters

Removing excessive whitespace

Tokenization

This step ensures consistency across all downstream models.

Feature Engineering Layer Three different feature representations are created:

TF-IDF vectors for statistical modeling

Word2Vec averaged embeddings for semantic representation

Tokenized padded sequences for deep learning (LSTM)

Modeling Layer Each feature representation feeds into a suitable classifier:

Logistic Regression for TF-IDF

Random Forest for Word2Vec embeddings

LSTM neural network for sequential modeling

Evaluation Layer Model performance is evaluated using Accuracy, Precision, Recall, and F1-score to ensure fair comparison.

Decision Layer Based on empirical results and business constraints, the best-performing and most interpretable model is selected for deployment.

This modular design allows easy replacement or extension of individual components without altering the entire pipeline.

3.2 Preprocessing Pipeline¶

Problem: Raw text data contains "noise" that confuses machine learning models. Email addresses, special characters, and varying capitalizations (e.g., "Car" vs "car") increase the dimensionality of the data without adding semantic value.

Solution: We implement a cleaning function preprocess_text that performs:

  1. Lowercasing: Standardizes all text.
  2. Regex Cleaning: Removes non-alphabetical characters and email addresses to protect privacy and reduce noise.
  3. Lemmatization: Converts words to their root form (e.g., "running" $\rightarrow$ "run"). This reduces the total vocabulary size, making the models more efficient.
In [7]:
# 2. Preprocessing Pipeline
stop_words = set(stopwords.words('english'))
lemmatizer = WordNetLemmatizer()

def preprocess_text(text):
    # a. Lowercase
    text = text.lower()
    
    # b. Remove emails (privacy/noise reduction)
    text = re.sub(r'\S+@\S+', '', text)
    
    # c. Remove special characters/numbers (keep letters only)
    text = re.sub(r'[^a-zA-Z\s]', '', text)
    
    # d. Remove extra whitespace
    text = re.sub(r'\s+', ' ', text).strip()
    
    # e. Tokenization & Lemmatization
    words = text.split()
    words = [lemmatizer.lemmatize(w) for w in words if w not in stop_words and len(w) > 2]
    
    return ' '.join(words)

4.1 Model A: Statistical Approach (TF-IDF)¶

Concept: TF-IDF (Term Frequency-Inverse Document Frequency) converts text into numbers based on word importance. It gives high weight to unique words that appear frequently in a specific document but rarely elsewhere (e.g., "orbit" in Space docs).

Implementation:

  • Vectorizer: Converts the top 5,000 words into a sparse matrix.
  • Classifier: We use Logistic Regression. This is a linear model that works exceptionally well with high-dimensional sparse data like TF-IDF. It tries to find a linear boundary that separates the four topics.

4.2 Model B: Semantic Approach (Word2Vec)¶

Concept: Unlike TF-IDF, which counts words, Word2Vec captures meaning. It maps words to a 100-dimensional vector space where similar words are mathematically close (e.g., "car" is close to "truck").

Implementation:

  1. Training Embeddings: We train a Word2Vec model from scratch on our training data.
  2. Document Representation: Since Word2Vec gives a vector for each word, we average all word vectors in a message to get a single vector representing the entire document.
  3. Classifier: We use a Random Forest. Since averaged vectors are dense and complex, a non-linear tree-based model often performs better than linear regression here.

def get_doc_vector(model, tokens):
    words = [word for word in tokens if word in model.wv]
    if len(words) >= 1:
        return np.mean(model.wv[words], axis=0)
    else:
        return np.zeros(model.vector_size)

4.3 Model C: Deep Learning Approach (LSTM)¶

Concept: Traditional models (TF-IDF, Word2Vec Average) ignore word order ("Dog bites man" = "Man bites dog"). LSTMs (Long Short-Term Memory) are Recurrent Neural Networks designed to read text sequentially, remembering context from the beginning of the sentence to understand the end.

Architecture:

  1. Embedding Layer: Learns dense vector representations for words during training.
  2. SpatialDropout: A regularization technique to prevent overfitting.
  3. LSTM Layer: The core memory unit that processes the sequence.
  4. Dense Output: A softmax layer that outputs the probability for each of the 4 categories.

6. Discussion and Recommendations¶

Performance Analysis: Looking at the results, the TF-IDF + Logistic Regression model surprisingly outperformed the Deep Learning (LSTM) model. I suspect this is because the dataset, while 'uncleaned', didn't have enough samples (under 20k) for the LSTM to fully learn complex patterns. The Word2Vec model was stable but computationally slower to train.

Challenges Faced:

  • Data Cleaning: One major challenge I faced was handling the raw headers and footers. The noise from email signatures initially confused the models, so I had to refine my Regex patterns in the preprocessing step to strictly filter for alphanumeric characters.
  • Overfitting: The LSTM model quickly started overfitting (memorizing the training data), which I mitigated by adding SpatialDropout layers.

Final Recommendation: For the company, I would deploy the TF-IDF Logistic Regression model first. It is fast, easy to explain to stakeholders, and currently yields the highest F1-score. We can revisit Deep Learning later once we have accumulated a larger database of labeled internal emails.
